## 1. Объект и точки использования

`Duration` — обёртка над `uint64_t valueMicros` (микросекунды): фабрики, арифметика,
сравнения, конверсия `operator uint64_t()`. Конструктор **protected** — создание
только через фабрики.

| Точка | Как используется | Файл:строки |
|---|---|---|
| `Task::delay/interval` | Владение `Duration*`, освобождение в `~Task` (алиасинг-гард — фикс #1) | `Task.h:20-21`, `Task.cpp:25-48` |
| Армирование Active-таймера | `delay->us()` — микросекунды в `esp_timer_start_once` | `Task.cpp:203` |
| Дедлайны Light/Deep | Неявная конверсия `(uint64_t) getDelay()` в **шкале rts_us** | `Task.cpp:216-217, 232-233, 279-280` |
| Шаг REPEAT | `getNext() + getInterval()` (неявная конверсия) | `Executor.cpp:91, 95` |
| Примеры | `Duration::ms(...)`/`zero()` как аргументы `onDelay/onRepeat` (владение у Task); `examples/Duration` — держит `auto`-указатели и **течёт** (#16) | все `examples/` |

Ключевой контекст планировщика: `UINT64_MAX` в `next`/`deepTasksTimeFast` —
sentinel «бесконечность» (задача неактивна); шкала Light/Deep-дедлайнов — `rts_us()`
(gettimeofday), Active — `esp_timer` (см. #25 о их смешении).

## 2. Что хорошо (сохранить при рефакторинге)

- **Защита вычитания** от underflow во всех трёх местах: `subtract` (`:24-26`),
  `operator-(Duration)` (`:103-105`), `operator-(uint64_t)` (`:127-129`) — кламп в 0.
- **Защита деления** от нуля: `:111-113`, `:119-121`.
- **Self-assign-гард** в `operator=` (`:69`).
- **Алиасинг `delay==interval`** в `~Task` закрыт фиксом #1 — `Duration*` не
  удаляются дважды.
- Неявная `operator uint64_t()` во всех точках использования отрабатывает корректно,
  рассинхрона объявлений и определений нет.

## 3. Находки

### F1 🟡 Смешение семантик «длительность» и «момент времени»
**Где:** `Duration.cpp:48-50` (`now()`), `:28-34` (`after`/`before`).
`Duration` — одновременно интервал («500 мс») и таймстемп (`now()`). `after()/before()`
для интервала — «дольше, чем», для момента — «позже, чем»; тип не различает.
Пример вреда — сам `examples/Duration`: сравнение двух статических интервалов
печатает бессмысленное «3 seconds have not yet passed».

### F2 🟡 `now()` в шкале `esp_timer`, а не `rts_us`
**Где:** `Duration.cpp:48-50`.
Дедлайны Light/Deep планировщика — `rts_us()` (`Task.cpp:216/:232`). Пользовательский
`Duration::now() + Duration::ms(x)` даст дедлайн в шкале esp_timer — она не идёт во
время сна, и после первого light/deep сна такой дедлайн разъедется с реальностью.
Родственно #25 (там обратная сторона — смешение шкал внутри Executor).

### F3 🟡 Сложение без сатурации; `maximum()` конфликтует с арифметикой
**Где:** `:20-22`, `:99-101`, `:123-125` (сложение), `:52-54` (`maximum`).
`add`/`operator+` молча переполняются. `maximum()` = `UINT64_MAX` — это же sentinel
планировщика «бесконечность»; `maximum() + Duration::ms(1)` → wrap в **0** →
дедлайн «уже наступил» → задача сработает немедленно. Тихо и неотлаживаемо.

### F4 ⚪ Геттеры не const
**Где:** `:36-46` — `us()/ms()/sec()` без `const`: нельзя вызвать на
`const Duration&`/`const Duration*`.

### F5 ⚪ Фабрики усекают аргументы
**Где:** `:60-66` — `us(uint32_t)`, `ms(uint32_t)` при 64-битном хранилище:
`Duration::ms(5'000'000'001ULL)` молча даст не то. Ловится только на больших числах.

### F6 ⚪ Размерно бессмысленные операторы
**Где:** `:107-113` — `Duration*Duration` (мкс²) и `Duration/Duration`
(безразмерное, завёрнутое обратно в Duration). Компилируются, дают числовой мусор
по смыслу; усугубляют F1.

### F7 ⚪ `zero()` аллоцирует; смешанное владение фабрик
**Где:** `:56-66` против `:48-54`; суть — issues.md **#16**.
`zero()/us()/ms()` возвращают владеющий `Duration*`, `now()/maximum()` — по значению.
Естественное `auto d = Duration::ms(1500)` течёт (так делает сам `examples/Duration`);
освобождение — только неявно через `onDelay/onRepeat`, забирающие указатель.
`zero()` при этом аллоцирует `new` ради константы.

### F8 ⚪ Док-комментарии Duration.h показывают невалидный код
Примеры во всех док-блоках: `Duration d1(1000);` — конструктор protected, у
пользователя **не скомпилируется**; `Serial.println(now.get())` — метода `get()`
нет. Про владение фабрик-указателей доки молчат — подталкивают к утечкам #16.

### F9 ⚪ Прочие шероховатости
Нет `+=/-=`; `set()` делает «value object» мутируемым (нужно ли?); свободного
`operator+(uint64_t, Duration)` нет (ассиметрия: `d + 5` ок, `5 + d` — нет).

## 5. Рекомендации по исправлению

### Этап 1 — безопасное API, низкий риск (можно делать сразу)

- **R1 (F4):** сделать `us()/ms()/sec()` `const`. Обратно совместимо (вызовов на
  const-объектах сейчас нет — расширение, не ломка).
  ```cpp
  uint64_t Duration::us() const { return valueMicros; }
  uint64_t Duration::ms() const { return valueMicros / 1000ULL; }
  uint64_t Duration::sec() const { return ms() / 1000ULL; }
  ```
- **R2 (F5):** расширить фабрики до `uint64_t`: `us(uint64_t)`, `ms(uint64_t)`.
  Существующие вызовы с `uint32_t`-литералами совместимы.
- **R3 (F3):** сатурация в сложении (все три варианта):
  ```cpp
  static uint64_t satAdd(uint64_t a, uint64_t b) {
      return (a > UINT64_MAX - b) ? UINT64_MAX : a + b;
  }
  ```
  и в `operator*(uint64_t)` — кламп при `factor && valueMicros > UINT64_MAX / factor`.
  `maximum()` в док-комментарии пометить как sentinel «бесконечность планировщика»:
  **складывать с ним нельзя** (после сатурации `maximum()+x` останется `maximum()` —
  это и есть желаемая семантика).
- **R4 (F8):** переписать примеры в док-комментариях Duration.h на компилируемые
  (`Duration d = Duration::maximum();`, фабрики по значению после R10 либо явные
  `Duration * d = Duration::ms(5); … delete d;`) и добавить раздел «Владение»
  (кто освобождает: Task при onDelay/onRepeat; локальный указатель — вручную).
- **R5 (F7, частично):** `zero()` без аллокации — вернуть значение (см. R10);
  если R10 откладывается, оставить как есть и задокументировать.

**Верификация этапа 1:** `pio run -e duration -e executor_light -e pin_tone`
(задевают Duration); стендом — `duration` (значения те же) и `pin_tone`
(частоты те же). Регресс не ожидаем: правки аддитивные.

### Этап 2 — семантика и шкала (координация с #25)

- **R6 (F1, F2):** не плодить типы сейчас. Ввести `Duration::nowRts()`
  (`rts_us()`) для «моментов» в шкале планировщика; у `now()` док-пометку:
  «шкала esp_timer — только для измерения интервалов бодрствования, во сне стоит».
  В будущем (после §6.5 EXECUTOR.md) — один источник истины: `now()` планировщика
  и `Duration::now()` обязаны совпадать.
- **R7 (F6):** удалить `operator*(Duration)` и `operator/(Duration)` (или вернуть
  `uint64_t` из деления). Скалярные `operator*(uint64_t)`/`operator/(uint64_t)`
  оставить. Греп использования в библиотеке/примерах — их нет, удаление безопасно.
- **R8 (F9):** добавить `operator+=/-=` по желанию; свободный
  `operator+(uint64_t, const Duration&)`; рассмотреть удаление `set()` (мутация
  value-object без потребителей — греп).

### Этап 3 — владение (#16, самое инвазивное)

- **R9 (F7, корень #16):** единый стиль — **фабрики по значению**
  (`Duration Duration::ms(uint32_t)`; C++17 гарантирует отсутствие копии).
  `onDelay/onRepeat` получают перегрузки по значению и сами кладут копию в кучу
  (`new Duration(std::move(v))`) для `Task::delay/interval`; указательные перегрузки
  пометить как legacy (или оставить только для явной передачи владения).
- **R10:** миграция примеров с `Duration::ms(...)`-указателей на значения;
  `examples/Duration` перестаёт течь. `Boot`/`State` и остальные примеры —
  механическая замена сигнатур.

**Верификация этапа 3:** полный `pio run` по всем env + стендовая перепроверка
`duration`, `boot`, `executor_*`, `state_sleep_modes` (владение и тайминги не
изменились), плюс контроль кучи в `debugging` (free heap до/после цикла примера
Duration — утечка должна исчезнуть).
