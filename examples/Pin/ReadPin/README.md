# Pin / ReadPin

`Pin::digitalRead` — чтение уровней GPIO опросом: два пина, программная детекция
фронтов (логируются только переходы). До 2026-11-08 пример был копией старого
interrupt-каркаса (issues.md #26) — переписан по назначению.

## Что демонстрирует

- опрос `digitalRead()` из задачи планировщика (`onRepeat<Active>` каждые 50 мс);
- состояние уровней — в самой лямбде (`mutable`), логируется только изменение
  с таймстампом (`rts_ms`);
- `analogRead` не показан: АЦП — только ADC1 (GPIO32-39), пины стенда другие.

## Отчёт о проверке

- **Дата:** 2026-11-08
- **Стенд:** DUT `esp32dev` (COM11) + стимулятор ESP32-C3 (COM12, см.
  `auxiliary/`): GPIO13/GPIO15 DUT соединены с каналами 4/5 (C3 GPIO6/GPIO7);
  команда `SET` меняет уровень линии — пример обязан увидеть переход с задержкой
  не больше периода опроса
- **Фреймворк:** Arduino-ESP32 **3.3.5**, ESP-IDF **5.5.1** (`pioarduino#55.03.35`)
- **Результат: OK.** Стартовые уровни по pull (0/0); все 5 стимул-событий
  (включая два перехода в одну миллисекунду на разных пинах) пойманы, задержка
  детекции 27–97 мс — в пределах периода опроса.

```
I (7)    MAIN: start: pin13=0 pin15=0
I (2824) MAIN: pin13: 0 -> 1 (t=2727 ms)
I (4624) MAIN: pin13: 1 -> 0 (t=4527 ms)
I (6374) MAIN: pin15: 0 -> 1 (t=6277 ms)
I (8174) MAIN: pin13: 0 -> 1 (t=8077 ms)
I (9974) MAIN: pin13: 1 -> 0 (t=9877 ms)   <- два перехода на разных пинах
I (9974) MAIN: pin15: 1 -> 0 (t=9877 ms)      в одном цикле опроса
```

## Сборка и прошивка

```bash
pio run -e pin_read -t upload
PYTHONIOENCODING=utf-8 pio device monitor -p COM11
```
